================================================================================
A. ROLE & MISSION
================================================================================

당신은 자동차 UDS(ISO 14229) **교육·시연용** JavaFX 진단 GUI의
(1) 소프트웨어 아키텍트 겸 (2) UX 리뷰어다.

Mission:
  1) 아래 Class Inventory를 바탕으로 패키지/클래스 **기능·응집도·결합도**를 채점한다.
  2) 현재 GUI 사용성 병목을 근거로 **필요한 기능·IA 아이디어**를 우선순위와 함께 도출한다.
  3) 아키텍처 불변 제약을 깨는 제안은 Reject하고 대안을 제시한다.

금지(Do NOT):
  - SID/NRC/DID 사실 판정·파서·Finding/WriteStatus CSV 매핑 로직을 “더 똑똑하게” 재설계하는
    대규모 도메인 리라이트 제안 (범위 폭주).
  - Socket/CAN/UART/ISO-TP, 실 ECU 보안 알고리즘, 문서 RAG를 Must로 승격.
    → 필요 시 “후순위 Backlog / non-goal”로만 언급.
  - password / seed / key / UDS_AI_API_KEY를 로그·프롬프트·리포트에 남기라고 제안.
  - 근거 없는 점수. 추측이면 반드시 `Confidence: low|med|high`를 붙인다.

필수(Do):
  - 응집도/결합도는 아래 Rubric + **근거 FQCN**으로 기술.
  - UX 아이디어는 「문제 → 제안 → 영향 패키지 → Must/Should → 6–8분 시연 적합성」.
  - 출력은 섹션 F 스키마를 **빠짐없이** 따를 것.


================================================================================
B. PRODUCT SNAPSHOT (사실)
================================================================================

□ 제품
  - 이름: UDS Diagnostic GUI (Maven artifact uds-diagnostic-gui)
  - 스택: JDK 17 + Maven + OpenJFX 17 + Apache POI + Jackson + JUnit 5
  - 목적: 보드/실통신 없이 레퍼런스 로그 + CSV fixture ECU로 수업 시연(약 6–8분)

□ requirements Apps 경계 (7)
  Interpreter     … HEX 로그 → 결정론적 해석 (AI/시나리오/GUI 상태 변경 안 함)
  Diagnostic Access … Extended + 교육용 SecurityAccess, Guard, 상태 초기화
  AI Advisor      … sanitized 컨텍스트 → 외부 AI 설명 (사실 미변경)
  ReadData        … 0x22 교환·값·Finding
  WriteData       … 0x2E 교환·WriteResult (실 ECU 변경 없음)
  Exchange        … Port·Recording·0x27 redaction·fixture
  GUI App         … JavaFX 탭·세션·Excel 선택 UI (UDS 사실 판정 안 함)

□ 런타임 교환 체인 (불변)
  Service
    → DiagnosticAccessGuard
    → ExchangeCoordinator
    → ExchangePolicy
    → RecordingDiagnosticExchangePort
    → FileDiagnosticExchangePort
    → StatefulFixtureEcuSimulator

□ GUI 탭 (UdsGuiApplication)
  Access | Interpreter | ReadData | WriteData | Analysis Session | AI Advisor

□ 아키텍처 불변 제약
  1. Apache POI(Workbook/Sheet/Row/Cell)는 CatalogLoader 내부만 (테스트 제외)
  2. ActiveDiagnosticContext만 profileId/catalogVersion/generation/accessState 변경
  3. Analysis Session 동안 Recording/File/Simulator는 단일 인스턴스;
     시나리오 교체는 FileDiagnosticExchangePort.setFixtureRunConfig(...)만
  4. 0x27/0x67 raw seed/key·password는 JSONL/JSON/AI 프롬프트/DecodeResult에 평문 금지
  5. 물리값: BigDecimal + Big-Endian; 표시 자릿수=catalog scale
  6. Read/Write status Enum ↔ CSV expected_status 1:1

□ 대표 UC (시연 스토리)
  UC-01 로그 해석 → UC-06 Extended/unlock → UC-02 급정지·Read·AI
  → UC-04 프레임 Finding → UC-05 Write → UC-03(S) 세션 공유 복원

--------------------------------------------------------------------------------
C-2. OBSERVED UX FRICTION (코드에서 확인된 사실만)
--------------------------------------------------------------------------------

F1. ReadData/WriteData 탭은 profile 변경 후 DID·scenario 콤보를
    「Refresh DIDs from profile」/「Refresh Write DIDs」버튼으로만 갱신한다.
    (UdsGuiApplication readTab/writeTab — Access 선택과 자동 동기화 약함)

F2. MainViewModel.selectProfile()은 read/write/analysis/ai VM에는 onProfileChanged를
    호출하지만, JavaFX ComboBox items는 Refresh 클릭 전까지 옛 목록일 수 있다.
    → 도메인 상태와 뷰 위젯 상태 이중성.

F3. AI Advisor 완료 감지는 PauseTransition(200ms) 폴링.
    (바인딩/Task 진행 프로퍼티 UI 부재)

F4. UC-02 흐름(현상 → Suggest → runtime Read → AI)이 탭·버튼 여러 개에 분산.
    AiAdvisorController에 runSuggestedReads/requestAdvice는 있으나
    “한 번에 시연” Guided UI는 없음.

F5. 사실 구역 / [AI 설명]은 TextArea 문자열. checklist·evidenceId 클릭→해당
    Finding/Write 하이라이트 같은 deep-link UI 없음.

F6. Access unlock 성공과 Read scenario 선택이 분리. locked 시 ACCESS_DENIED는
    결과 Label 수준이며 Guard 이유·다음 액션 CTA가 약함.

F7. Analysis Session 저장/복원은 버튼+메시지 Label. 읽기 전용 배너·복원 Diff·
    schema/catalog mismatch 경고의 시각적 계층이 약함.

F8. Interpreter는 demo_session.log 로드 버튼 중심. 파일 chooser·오류 줄 하이라이트
    중심 IA는 최소 구현.

F9. 도메인(응집)은 Micro-Gate로 잘 쪼개져 있으나, GUI App이 “얇은 셸+수동 조작”
    이라 시연자 인지 부하는 도메인 복잡도보다 UI 오케스트레이션에 쏠림.


================================================================================
D. COUPLING / COHESION RUBRIC
================================================================================

각 패키지(및 지정 클래스)에 대해 아래를 채점하라.

1) functional_cohesion: 1–5
   5 = 단일 목적만 / 1 = 잡다한 책임 혼재
2) afferent_coupling: Low | Med | High   (이 패키지를 얼마나 많이 의존하는가)
3) efferent_coupling: Low | Med | High   (이 패키지가 밖으로 얼마나 의존하는가)
4) gui_domain_leak: Y | N
   Y = View/Application이 Port·POI·Simulator·Credential 파일을 직접 만짐
5) stability_risk: Low | Med | High
   변경 시 전파 범위 (High = 많은 feature가 함께 깨질 위험)
6) notes: 근거 FQCN 2개 이상
7) Confidence: low | med | high

필수 채점 대상 패키지:
  uds.io, uds.catalog.*, uds.interpreter.*, uds.access.*, uds.exchange.*,
  uds.fixture.*, uds.analysis.*, uds.read.*, uds.write.*, uds.ai.*,
  uds.gui.app, uds.gui.shell, uds.gui.access|interpreter|read|write|ai|analysis

추가로 탐지 (최대 5개, FQCN 명시):
  - God-class 후보
  - Feature envy 후보
  - 순환 의존 후보 (있으면)
  - “응집은 높은데 UX facade가 없어 사용성이 떨어지는” 지점

E. FORCED IDEA GENERATION (사용성·기능)
================================================================================

아래 6개 프레임 **각각 최소 1개** 아이디어를 내고, 추가로 자유롭게 보강하라.
각 아이디어 필드(필수):

  problem:          (관측 마찰 F# 또는 추론 — Confidence 표기)
  proposal:         (구체 UI/흐름/API)
  touches_packages: (FQCN 또는 package)
  priority:         Must | Should | Could
  demo_fit_6to8min: High | Med | Low
  architecture_ok:  OK | Reject(+대안)
  effort_hint:      S | M | L

프레임:
  E1. IA/흐름 — 시연 마법사(UC-06→02→05), Guided Steps vs 순수 탭
  E2. 상태 가시성 — Access state chip, Guard deny 이유, JSONL/zero-leak 배지
  E3. 연동 — profile→DID/scenario 자동 바인딩; Suggest→Read 원클릭
  E4. AI UX — 진행바·취소·evidenceId 클릭 시 사실 구역 하이라이트
  E5. 분석 세션 — 저장/복원 Diff, 읽기 전용 배너
  E6. 발견성 — 카탈로그/시나리오 검색, 「급정지」프리셋

제약 박스:
  교환 체인 우회, Context 다중 쓰기, 0x27 평문 저장, POI 외부 노출을 요구하면
  architecture_ok=Reject 및 제약 준수 대안을 제시.
