[TASK: Phase 3 — UDS-UX-02 구현·테스트·검증]
`uds.gui.**` 패키지 내에서 작업하여 UDS-UX-02 (상단 Global Diagnostic Status Bar 및 ACCESS_DENIED 복구 CTA)를 수행하라.

### 1단계: 구현 (Implementation)
1. 상태 노출 (`MainViewModel` / `AccessViewModel`):
   - `ActiveDiagnosticContext`의 읽기 전용 Snapshot으로부터 현재 상태를 반영하는 표시용 프로퍼티/문자열을 `MainViewModel`(또는 `AccessViewModel`)에 노출하라:
     * Profile ID (예: `Profile: <id>`)
     * Diagnostic Session (예: `Session: DEFAULT` / `EXTENDED`)
     * Security State (예: `Security: LOCKED` / `UNLOCKED`)
     * Redaction Badge (`0x27 Redaction: ON` 상시 표시)
   - 주의: 불변 제약 2에 따라 `ActiveDiagnosticContext`를 직접 수정하는 setter를 GUI에 만들지 말고, 프로필 선택/세션 전환/Unlock/복원 등 상태 변화 이벤트 시 읽기 전용 스냅샷만 갱신 구독하라.
2. ACCESS_DENIED 상태 및 탭 전환 콜백 (`ReadDataViewModel`, `WriteDataViewModel`, `MainViewModel`):
   - Read 또는 Write 수행 결과가 `ACCESS_DENIED`일 때, 거부 사유 안내 문구(예: "권한 부족: Extended 세션 및 Security Unlock이 필요합니다")와 함께 Access Denied 상태 플래그(`BooleanProperty accessDeniedProperty()`)를 활성화하라.
   - 성공적인 Read/Write 또는 Access Unlock 성공 시 해당 플래그가 해제되도록 하라.
3. View 조립 (`UdsGuiApplication`):
   - `TabPane` 상단(BorderPane top 등)에 모든 탭에서 공통으로 보이는 **Global Diagnostic Status Bar** (Chip 스타일 Label 4개)를 배치하라.
   - ReadData 탭과 WriteData 탭의 결과 영역에 `ACCESS_DENIED` 발생 시에만 노출되는 경고 배너와 `[Access 탭으로 이동하여 Unlock]` CTA 버튼을 추가하라.
   - 해당 CTA 버튼 클릭 시 `TabPane`의 선택 탭이 즉시 `Access` 탭으로 전환되도록 연결하라.

### 2단계: 테스트 (Testing)
- ViewModel 단위 테스트를 작성/보강하라:
  1) 초기 상태(Default/Locked) → Extended 전환 → Security Unlock 성공 시 Status Bar용 상태 프로퍼티가 정확히 동기화되는지 검증.
  2) Locked 상태에서 Read/Write 시도 시 `ACCESS_DENIED` 상태 플래그와 안내 메시지가 활성화되는지 검증.

### 3단계: 검증 (Verification)

3. 결과를 요약 보고하고 다음 지시를 대기하라.
