[TASK: Phase 2 — UDS-UX-03 구현·테스트·검증]
`uds.gui.app` 및 `uds.gui.ai` 패키지 내에서만 작업하여 UDS-UX-03 (PauseTransition 폴링 제거 및 UiTaskRunner 반응형 진행/취소 바인딩)을 수행하라.

### 1단계: 구현 (Implementation)
1. `uds.gui.app.UiTaskRunner` 확장:
   - 기존 `CompletableFuture` + `ExecutorService` + `orTimeout(15s)` 및 헤드리스 호환 구조(FX 툴킷 미기동 시 inline 실행 폴백)를 깨뜨리지 마라.
   - 실행 상태를 관찰할 수 있도록 JavaFX 프로퍼티(`BooleanProperty runningProperty()`, `StringProperty statusMessageProperty()` 등) 또는 완료/실패/취소 시 FX 스레드에서 호출되는 명시적 콜백 훅을 추가하라.
   - 진행 중인 작업을 즉시 취소하는 `cancelCurrent()` (또는 핸들 취소) 기능을 명확히 노출하라.
2. `uds.gui.ai.AiAdvisorController` 연동:
   - AI 요청 중 상태(`runningProperty`), 상태 메시지, 취소 액션을 Controller 프로퍼티/메서드로 노출하라.
   - 취소 또는 15초 타임아웃 발생 시 `AiError` 사유를 명확한 배너용 상태 문자열로 설정하되, 기존에 수집된 결정론적 Finding/사실 구역 데이터는 절대 지우지 말고 그대로 유지하라.
3. `uds.gui.app.UdsGuiApplication` (`aiTab()`) 수정:
   - `aiTab()` 내부의 `PauseTransition(200ms)` 폴링 코드를 완전히 제거하라.
   - 대신 `AiAdvisorController`(및 `UiTaskRunner`)의 프로퍼티/콜백에 `ProgressIndicator`(또는 `ProgressBar`), 상태 라벨, `[Cancel]` 버튼을 선언적으로 바인딩하라.
   - AI 요청 실행 중(`running == true`)에는 Ask/요청 버튼이 자동 비활성화(`disableProperty`)되게 하라.

### 2단계: 테스트 (Testing)
- `UiTaskRunnerTest` 및 `AiAdvisorControllerTest`에 다음 단위 테스트를 추가/갱신하라:
  1) 비동기 작업 시작 시 `running` 상태가 `true`가 되고 완료/예외 시 `false`로 복귀하는지 검증.
  2) 작업 중 `cancel` 호출 또는 타임아웃 발생 시 `AiError`가 기록되고, 기존의 Finding/사실 목록은 손실 없이 보존되는지 검증.
  3) `UdsGuiApplication.java` 소스 내에 `PauseTransition` 참조가 0건인지 확인.

### 3단계: 검증 (Verification)
1. 터미널에서 `mvn test`를 실행하여 전체 테스트 통과를 확인하라.
2. 불변 제약 점검: `UDS_AI_API_KEY`나 민감 정보가 에러 메시지나 로그에 노출되지 않는지 확인하라.
3. 결과를 요약 보고하고 다음 지시를 대기하라.
