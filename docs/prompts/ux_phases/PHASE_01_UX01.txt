[TASK: Phase 1 — UDS-UX-01 구현·테스트·검증]
`uds.gui.**` 패키지 내에서만 작업하여 UDS-UX-01 (Profile 변경 시 Read/Write DID·시나리오 ComboBox 자동 바인딩)을 수행하라. 도메인 패키지는 수정하지 마라.

### 1단계: 구현 (Implementation)
1. 대상 파일 확인:
   - `uds.gui.read.ReadDataViewModel`
   - `uds.gui.write.WriteDataViewModel`
   - `uds.gui.shell.MainViewModel`
   - `uds.gui.app.UdsGuiApplication` (`readTab()`, `writeTab()`)
2. ViewModel 리팩토링:
   - `ReadDataViewModel`의 runtime DID 목록 및 read scenario 목록을 `javafx.collections.ObservableList`로 노출(또는 내부 `ObservableList`가 `onProfileChanged` 호출 시 즉시 `setAll(...)` 되도록 수정)하라.
   - `WriteDataViewModel`의 write DID 목록 및 write scenario 목록도 동일하게 `ObservableList`로 노출하고 `onProfileChanged` 시 즉시 `setAll(...)`로 갱신하라.
   - 목록 갱신 직후 현재 선택된 DID/scenario 프로퍼티(또는 기본 선택 인덱스)를 첫 번째 유효 항목(목록이 비어있으면 null-safe)으로 자동 초기화하라.
3. View(`UdsGuiApplication`) 바인딩 연결:
   - `readTab()`과 `writeTab()`의 DID/scenario `ComboBox`가 VM의 `ObservableList`를 직접 바인딩(또는 VM 선택 프로퍼티와 동기화)하도록 연결하라.
   - 프로필 변경 직후 ComboBox의 선택값도 VM의 초기화된 첫 항목을 자동으로 가리키게 하라.
   - 기존의 수동 「Refresh DIDs from profile」 / 「Refresh Write DIDs」 버튼 의존성을 제거하거나 단순 재동기화 보조 버튼으로 격하하라(자동 갱신이 기본이어야 함).

### 2단계: 테스트 (Testing)
- JavaFX 툴킷 없이도 실행 가능한 ViewModel 단위 테스트(`ReadDataViewModelTest`, `WriteDataViewModelTest`, `MainViewModelTest` 등 기존 테스트 파일 또는 신규 테스트)를 추가/보강하라.
- 테스트 시나리오:
  1) `MainViewModel.selectProfile(newProfileId)` 호출 시 `ReadDataViewModel`과 `WriteDataViewModel`의 `ObservableList` 항목이 즉시 새 프로필의 `runtime_enabled` 목록으로 변경되는지 검증.
  2) 프로필 변경 후 선택된 기본 DID가 이전 프로필의 잔재가 아닌 새 프로필의 유효 첫 항목(또는 null)인지 검증.

### 3단계: 검증 (Verification)
1. 터미널에서 `mvn test`를 실행하여 기존 Micro-Gate 테스트와 신규 테스트가 100% 통과하는지 확인하라.
2. `git status` 및 `git diff`로 `uds.gui.**` 외의 도메인 파일이나 `CURRENT.txt`가 수정되지 않았는지 확인하라.
3. 결과를 요약 보고하고 다음 지시를 대기하라.
