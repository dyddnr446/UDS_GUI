[TASK: Phase 4 — UDS-UX-04 구현·테스트·검증]
`uds.gui.ai`, `uds.gui.shell`, `uds.gui.app` 내에서 작업하여 UDS-UX-04 (원클릭 진단 파이프라인 및 Evidence Chip 하이라이트)를 수행하라.

### 1단계: 구현 (Implementation)
1. `AiAdvisorController` — 원클릭 파이프라인 및 구분 표시:
   - 현상(Symptom) 선택 후 한 번의 액션으로 ① `Suggest` (후보 DID 도출) → ② `runtime 실행 가능 DID 일괄 Read` (`runSuggestedReads`) → ③ `AI 설명 요청` (`requestAdvice`)을 순차 실행하는 `runOneClickDiagnosis()` 메서드를 구현하라.
   - 후보 DID 표시 시 정적 참고용 DID(`0xF186` 등 runtime 미실행 참고 항목)와 실제 runtime Read 대상 DID가 명확히 구분되어 리스트/텍스트에 표시되게 하라.
   - 만약 runtime Read 단계에서 모든 DID가 `ACCESS_DENIED`로 실패했다면 그 사실을 사실 구역에 명확히 남기고 안내하라.
2. `AiAdvisorController` & `UdsGuiApplication` (`aiTab()`) — 사실 구역 및 Evidence Chip 하이라이트:
   - 사실 구역(Findings / WriteResults / Evidence 목록)을 각 항목의 `evidenceId`(예: `EV-001`)로 식별·선택 가능한 `ListView`(또는 행 단위 선택/하이라이트가 가능한 컴포넌트)로 구성하라(기존 텍스트 요약 호환 유지 필요 시 병행 가능).
   - `AiAdviceResult` 수신 시 응답에 포함된 `evidenceIds` 목록을 클릭 가능한 Chip 버튼 영역(`FlowPane` 등)으로 렌더링하라.
   - 사용자가 특정 `[#evidenceId]` Chip을 클릭하면 사실 구역의 해당 `evidenceId` 항목이 선택(`select`) 및 스크롤(`scrollTo`)되어 시각적으로 하이라이트되게 하라.

### 2단계: 테스트 (Testing)
- `AiAdvisorControllerTest`에 다음 테스트를 추가하라:
  1) `runOneClickDiagnosis()` 호출 시 현상 후보 도출 → runtime DID Read 실행 → AI 조언 요청까지 한 번에 이어지는지 검증.
  2) `0xF186` 정적 참고 항목과 runtime 실행 DID가 구분되는지 검증.
  3) 특정 `evidenceId` 선택 시 Controller의 하이라이트 대상 ID 프로퍼티(또는 선택 항목)가 정확히 해당 증거 항목을 가리키는지 검증.

### 3단계: 검증 (Verification)
1. `mvn test`를 실행하여 전체 테스트 통과를 확인하라.
2. 불변 제약 점검: AI가 결정론적 Finding/Status를 덮어쓰지 않고 `AdvisorContextSanitizer`를 거친 컨텍스트만 사용하는지 확인하라.
3. 결과를 요약 보고하고 다음 지시를 대기하라.
