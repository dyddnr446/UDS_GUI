지금은 코드를 구현하기 전 [Step 0: SSOT 정합성 검증 게이트] 단계다.
아직 Java 프로덕션 코드는 작성하지 마라.

터미널에서 Python 일회성 검증 스크립트(파일 저장 없이 `py -3 -c "..."` 실행)를
실행하여 docs/requirements.xlsx, docs/uds_catalog.xlsx, samples/*.csv,
config/demo_password.txt를 읽고 아래 5가지를 검증해 결과만 표로 보고하라.

1. requirements.xlsx의 Functional(FR-01~FR-28), NonFunctional(NFR-01~NFR-21),
   UseCases(UC-01~UC-06), Completion(DOD-01~DOD-17) ID 목록과
   PROJECT_PLAN.txt 8.5절의 FR 매핑이 누락 없이 일치하는지 확인.

2. requirements.xlsx의 FR-13(현상-DID 제안) 요구/완료/확인 문구와
   PROJECT_PLAN.txt 7장 기능 D 문구를 대조:
   - uds_catalog.xlsx의 SymptomDidMap(0x1001~0x1005, 0x1007, 0xF186)과
     DidProfileSupport의 runtime_enabled=Y 필터 결과
     (ND72530: 0x1001, 0x1002, 0x1007 / Flipsky: 0x1001)가
     requirements.xlsx의 FR-13 셀 텍스트와 충돌하는 부분이 남아 있는지 확인.
   - 예전 문구가 남아 있으면 어느 셀을 어떻게 고쳐야 하는지 알려줄 것.

3. samples/read_data_scenarios.csv(11행)와 samples/write_data_scenarios.csv(12행)의
   모든 did, controller_profile 조합이 uds_catalog.xlsx의 DidProfileSupport에서
   runtime_enabled=Y 및 read_enabled=Y/write_enabled=Y와 100% 일치하는지 확인.

4. config/demo_password.txt에서 끝단 CRLF/LF 제거 후 "uds-demo-2026"과
   seed=AA BB CC DD, profileId="FARDRIVER_ND72530"으로 HMAC-SHA256 앞 4바이트
   계산 시 D3 AC 3F 47이 나오는지 확인.

5. 이상이 없으면 "Step 1A 진행 가능"을 선언하고 대기하라.
   (CURRENT.txt를 STEP_01A로 바꾸는 것은 사용자가 승인할 때.)
